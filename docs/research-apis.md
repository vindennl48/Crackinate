## 1. Screen Sleep Prevention

### 1a. NSProcessInfo.beginActivity (Recommended — Higher-Level API)

**Framework:** `Foundation`  
**Availability:** macOS 10.9+  
**Documentation:** https://developer.apple.com/documentation/foundation/nsprocessinfo/1417213-beginactivity

#### Signature

```swift
func beginActivity(
    options: ProcessInfo.ActivityOptions,
    reason: String
) -> NSObjectProtocol
```

#### ActivityOptions (Nested Type)

```swift
struct ActivityOptions : OptionSet {
    static var idleSystemSleepDisabled: ProcessInfo.ActivityOptions   // 1 << 20
    static var idleDisplaySleepDisabled: ProcessInfo.ActivityOptions  // 1 << 40
    static var suddenTerminationDisabled: ProcessInfo.ActivityOptions
    static var automaticTerminationDisabled: ProcessInfo.ActivityOptions
    static var userInitiated: ProcessInfo.ActivityOptions              // idleSystemSleep + suddenTerm + automaticTerm
    static var userInitiatedAllowingIdleSystemSleep: ProcessInfo.ActivityOptions
    static var userInteractive: ProcessInfo.ActivityOptions           // userInitiated + latencyCritical
    static var background: ProcessInfo.ActivityOptions
    static var latencyCritical: ProcessInfo.ActivityOptions
}
```

#### Usage

```swift
import Foundation

class ScreenSleepPreventer {
    private var activity: NSObjectProtocol?
    
    func enable() {
        guard activity == nil else { return }
        let options: ProcessInfo.ActivityOptions = [
            .idleSystemSleepDisabled,
            .idleDisplaySleepDisabled
        ]
        activity = ProcessInfo.processInfo.beginActivity(
            options: options,
            reason: "Crackinate: User requested keep-awake mode"
        )
    }
    
    func disable() {
        guard let a = activity else { return }
        ProcessInfo.processInfo.endActivity(a)
        activity = nil
    }
    
    var isActive: Bool { activity != nil }
}
```

#### Verification

```bash
pmset -g assertions | grep -A2 PreventUserIdle
```

#### Gotchas

- The returned `NSObjectProtocol` must be strongly retained. When deallocated, the assertion is released.
- `.userInitiated` alone does NOT prevent display sleep — must explicitly add `.idleDisplaySleepDisabled`.
- If the app crashes or terminates, assertions auto-release. No zombie assertions.
- Reason string appears in system diagnostics but NOT in Activity Monitor's "Preventing Sleep" column (unlike IOPMAssertion).

### 1b. IOPMAssertionCreateWithName (Alternative — Lower-Level API)

**Framework:** `IOKit.pwr_mgt`  
**Availability:** macOS 10.6+  
**Documentation:** https://developer.apple.com/documentation/iokit/iopmlib_h/iopmassertiontypes

#### Signature

```swift
import IOKit.pwr_mgt

func IOPMAssertionCreateWithName(
    _ assertionType: CFString,
    _ assertionLevel: IOPMAssertionLevel,
    _ reason: CFString,
    _ assertionID: UnsafeMutablePointer<IOPMAssertionID>
) -> IOReturn

func IOPMAssertionRelease(
    _ assertionID: IOPMAssertionID
) -> IOReturn
```

#### Assertion Types

| CFString Constant | Effect | Shows in Activity Monitor? |
|---|---|---|
| `kIOPMAssertionTypeNoIdleSleep` | Prevents idle system sleep (display may dim) | **No** |
| `kIOPMAssertionTypeNoDisplaySleep` | Prevents display sleep (also prevents idle sleep) | **Yes** (as "Preventing Sleep") |
| `kIOPMAssertionTypePreventSystemSleep` | Aggressively prevents all sleep including DarkWake | **Yes** |

#### Usage

```swift
import IOKit.pwr_mgt

class IOAssertionPreventer {
    private var assertionID: IOPMAssertionID = 0
    private var success: Bool = false
    
    func enable() {
        guard !success else { return }
        let result = IOPMAssertionCreateWithName(
            kIOPMAssertionTypeNoDisplaySleep as CFString,
            IOPMAssertionLevel(kIOPMAssertionLevelOn),
            "Crackinate: keeping display awake" as CFString,
            &assertionID
        )
        success = (result == kIOReturnSuccess)
    }
    
    func disable() {
        guard success else { return }
        IOPMAssertionRelease(assertionID)
        assertionID = 0
        success = false
    }
}
```

#### Gotchas

- No entitlements required.
- `kIOPMAssertionTypeNoIdleSleep` does NOT appear in Activity Monitor's "Preventing Sleep" list. Use `kIOPMAssertionTypeNoDisplaySleep` if you want visibility.
- Must manually release the assertion. Failure to release on app exit can leave the system awake (though macOS eventually garbage-collects orphaned assertions).

## 2. Lid-Close Sleep Prevention

### 2a. pmset disablesleep (The Only Reliable Method)

**Binary:** `/usr/bin/pmset`  
**Requires:** Root privileges (sudo)  
**Availability:** macOS 10.x+ (especially critical on Apple Silicon)

#### CLI Commands

```bash
# Disable all sleep (including lid-close)
sudo pmset -a disablesleep 1

# Re-enable
sudo pmset -a disablesleep 0

# Check status
pmset -g live | grep SleepDisabled
# Output:  SleepDisabled            1   (or 0)
```

#### Swift Process Wrapper

```swift
import Foundation

enum PmsetError: Error {
    case requiresRoot
    case commandFailed(String)
}

struct PmsetController {
    static func setDisableSleep(_ disable: Bool) throws {
        let value = disable ? "1" : "0"
        let task = Process()
        task.executableURL = URL(fileURLWithPath: "/usr/bin/pmset")
        task.arguments = ["-a", "disablesleep", value]
        task.standardOutput = Pipe()
        task.standardError = Pipe()
        
        try task.run()
        task.waitUntilExit()
        
        guard task.terminationStatus == 0 else {
            let errorData = (task.standardError as! Pipe)
                .fileHandleForReading.readDataToEndOfFile()
            let errorStr = String(data: errorData, encoding: .utf8) ?? "unknown"
            throw PmsetError.commandFailed(errorStr)
        }
    }
    
    static func isSleepDisabled() -> Bool {
        let task = Process()
        task.executableURL = URL(fileURLWithPath: "/usr/bin/pmset")
        task.arguments = ["-g", "live"]
        
        let pipe = Pipe()
        task.standardOutput = pipe
        
        do {
            try task.run()
            task.waitUntilExit()
        } catch {
            return false
        }
        
        let data = pipe.fileHandleForReading.readDataToEndOfFile()
        let output = String(data: data, encoding: .utf8) ?? ""
        
        // Parse "SleepDisabled  1" from output
        return output.contains("SleepDisabled") && 
               output.contains("1") &&
               !output.contains("SleepDisabled            0")
    }
}
```

#### Gotchas

- Setting persists across reboots. MUST explicitly set back to 0 to re-enable sleep.
- Only applies to lid-close sleep — does NOT affect idle system sleep from display/energy settings.
- Requires sudo. Without sudoers setup, each toggle prompts for password.
- Not App Store compatible. Apple rejects apps that disable lid-close sleep.
- Risk: Mac in bag with sleep disabled → overheating. Use thermal monitoring.

### 2b. Avoiding Password Prompts: sudoers File

**File:** `/etc/sudoers.d/crackinate`  
**Requires:** Root to create (one-time)

```bash
# One-time setup (run during app installation/setup)
echo "ALL ALL=(ALL) NOPASSWD: /usr/bin/pmset -a disablesleep 0, /usr/bin/pmset -a disablesleep 1" | sudo tee /etc/sudoers.d/crackinate
sudo chmod 440 /etc/sudoers.d/crackinate
```

#### Swift Installer

```swift
import Foundation

class SudoersInstaller {
    static func install() throws {
        let sudoersContent = """
        # Crackinate - passwordless pmset for lid-close sleep toggle
        ALL ALL=(ALL) NOPASSWD: /usr/bin/pmset -a disablesleep 0, /usr/bin/pmset -a disablesleep 1
        
        """
        
        // Write to temp file
        let tempPath = NSTemporaryDirectory() + "crackinate_sudoers"
        try sudoersContent.write(toFile: tempPath, atomically: true, encoding: .utf8)
        
        // Use AppleScript to get admin privileges for the move
        let script = """
        do shell script "cp \(tempPath) /etc/sudoers.d/crackinate && chmod 440 /etc/sudoers.d/crackinate && rm \(tempPath)" with administrator privileges
        """
        
        let appleScript = NSAppleScript(source: script)
        var error: NSDictionary?
        appleScript?.executeAndReturnError(&error)
        
        if let error = error {
            throw NSError(domain: "SudoersInstall", code: 1, 
                         userInfo: [NSLocalizedDescriptionKey: "\(error)"])
        }
    }
    
    static func isInstalled() -> Bool {
        FileManager.default.fileExists(atPath: "/etc/sudoers.d/crackinate")
    }
}
```

#### Gotchas

- `ALL ALL=` means all users — narrow if needed to a specific user.
- The file must NOT have a `.` in the name (sudo ignores files with dots).
- File must have permissions `0440`.
- Run `visudo -c` equivalent check after writing (or just verify with `sudo -l`).
- If sudoers file has syntax error, sudo breaks system-wide. Test carefully.

### 2c. Privileged Helper Tool via SMAppService (Alternative — More Complex)

**Framework:** `ServiceManagement`  
**Availability:** macOS 13+ (replaces deprecated SMJobBless)  
**Reference:** https://github.com/alienator88/HelperToolApp

This is the "proper" architecture — a root-level daemon bundled inside the app that communicates via XPC. The user approves once in System Settings, no password needed thereafter.

#### Architecture

```
┌──────────────────────┐          XPC (Mach Service)        ┌─────────────────────────┐
│   Crackinate (User)  │ ◄─────────────────────────────────► │  Helper Daemon (Root)   │
│                      │                                      │  Executes pmset         │
└──────────────────────┘                                      └─────────────────────────┘
```

#### Key Steps

1. Create a daemon executable target in Xcode (command-line tool)
2. Create a `launchd.plist` for the daemon embedded in `__TEXT,__launchd_plist` section
3. Bundle the daemon at `Contents/Library/LaunchDaemons/` in the app
4. Register: `try SMAppService.daemonService(plistName: "com.crackinate.helper.plist").register()`
5. Communicate via NSXPCConnection

#### Recommendation

**Use the sudoers approach instead.** SMAppService daemon adds 300+ lines of XPC protocol code, code signing complexity, and requires the user to dig through System Settings to approve. The sudoers approach is battle-tested by SleepOff and provides identical functionality with 10% of the code. Consider SMAppService only if planning Mac App Store distribution (which won't work for lid-close prevention anyway).

## 3. Lid State Detection

### IORegistry AppleClamshellState

**Framework:** `IOKit`  
**Source:** https://github.com/sabraman/sleepoff

```swift
import IOKit

func isLidClosed() -> Bool {
    let service = IOServiceGetMatchingService(
        kIOMasterPortDefault,
        IOServiceMatching("AppleClamshellState")
    )
    guard service != 0 else { return false }
    defer { IOObjectRelease(service) }
    
    guard let result = IORegistryEntryCreateCFProperty(
        service,
        "AppleClamshellState" as CFString,
        kCFAllocatorDefault,
        0
    ) else { return false }
    
    defer { result.release() }
    
    guard let dict = result.takeRetainedValue() as? [String: Any],
          let closed = dict["ClamshellState"] as? Bool else {
        return false
    }
    return closed
}
```

#### Gotchas

- This is a **polling** mechanism — no push notifications from IOKit for lid state changes.
- Poll every 1-2 seconds via `Timer.scheduledTimer`.
- On desktop Macs (iMac, Mac mini, Mac Studio), `AppleClamshellState` service doesn't exist — return false.
- The `ClamshellState` key returns `true` when lid is closed, `false` when open.

## 4. Display Dimming When Lid Closed

### CoreDisplay Private API

**Framework:** `/System/Library/Frameworks/CoreDisplay.framework/CoreDisplay`  
**Warning:** Private API. Not App Store compatible.

```swift
import CoreGraphics

typealias CoreDisplaySetBrightness = @convention(c) (
    CGDirectDisplayID, Double
) -> Void

func setBuiltinDisplayBrightness(_ level: Double) {
    let clamped = max(0.0, min(1.0, level))
    
    guard let handle = dlopen(
        "/System/Library/Frameworks/CoreDisplay.framework/CoreDisplay",
        RTLD_LAZY
    ) else { return }
    defer { dlclose(handle) }
    
    guard let sym = dlsym(
        handle,
        "CoreDisplay_Display_SetUserBrightness"
    ) else { return }
    
    let fn = unsafeBitCast(sym, to: CoreDisplaySetBrightness.self)
    fn(CGMainDisplayID(), clamped)
}

// Get current brightness
typealias CoreDisplayGetBrightness = @convention(c) (
    CGDirectDisplayID
) -> Double

func getBuiltinDisplayBrightness() -> Double {
    guard let handle = dlopen(
        "/System/Library/Frameworks/CoreDisplay.framework/CoreDisplay",
        RTLD_LAZY
    ) else { return 1.0 }
    defer { dlclose(handle) }
    
    guard let sym = dlsym(
        handle,
        "CoreDisplay_Display_GetUserBrightness"
    ) else { return 1.0 }
    
    let fn = unsafeBitCast(sym, to: CoreDisplayGetBrightness.self)
    return fn(CGMainDisplayID())
}
```

#### Implementation Pattern (from SleepOff)

```swift
class DisplayDimmer {
    private var savedBrightness: Double?
    private var didDim: Bool = false
    
    func onLidClosed() {
        guard !didDim else { return }
        savedBrightness = getBuiltinDisplayBrightness()
        setBuiltinDisplayBrightness(0.0)
        didDim = true
    }
    
    func onLidOpened() {
        guard didDim, let saved = savedBrightness else { return }
        setBuiltinDisplayBrightness(saved)
        didDim = false
        savedBrightness = nil
    }
}
```

#### Gotchas

- Only works on the **built-in** display (MacBook internal display).
- On Apple Silicon, IOKit brightness APIs may silently fail — CoreDisplay is the only reliable method.
- `dlopen` + `dlsym` avoids linking against the private framework (which would cause App Review rejection).
- Still detectable during notarization but typically passes for direct-distribution apps.

## 5. Thermal Safety

### NSProcessInfo.thermalState

**Framework:** `Foundation`  
**Availability:** macOS 10.10.3+  
**Documentation:** https://developer.apple.com/documentation/foundation/processinfo/thermalstate-swift.enum

```swift
enum ThermalState : Int {
    case nominal = 0  // Normal operating temperature
    case fair = 1     // Slightly elevated, system may throttle
    case serious = 2  // High temperature, significant throttling
    case critical = 3 // Dangerously hot, system will take aggressive action
}
```

#### Monitoring

```swift
class ThermalSafetyMonitor {
    static let shared = ThermalSafetyMonitor()
    var onThermalDanger: (() -> Void)?
    
    func start() {
        NotificationCenter.default.addObserver(
            self,
            selector: #selector(thermalStateDidChange),
            name: ProcessInfo.thermalStateDidChangeNotification,
            object: nil
        )
    }
    
    @objc private func thermalStateDidChange(_ notification: Notification) {
        let state = ProcessInfo.processInfo.thermalState
        
        switch state {
        case .nominal:
            print("Thermal: nominal — all clear")
        case .fair:
            print("Thermal: fair — monitoring")
        case .serious:
            print("Thermal: serious — warning user")
            onThermalDanger?()
        case .critical:
            print("Thermal: critical — FORCE DISABLING keep-awake")
            KeepAwakeManager.shared.disableAll()
            showCriticalThermalAlert()
        @unknown default:
            break
        }
    }
    
    private func showCriticalThermalAlert() {
        let alert = NSAlert()
        alert.messageText = "Critical Temperature"
        alert.informativeText = "Crackinate has disabled keep-awake mode to prevent overheating. Your Mac's temperature is critically high."
        alert.alertStyle = .critical
        alert.addButton(withTitle: "OK")
        alert.runModal()
    }
}
```

#### Gotchas

- Thermal events are system-wide, not per-app.
- `.critical` means the system is about to force-sleep or throttle aggressively — act immediately.
- This notification fires on the main thread.
- On Apple Silicon, thermal throttling is more aggressive than Intel — `.serious` may be more common.

## 6. AC Power Detection

### IOKit Power Sources

```swift
import IOKit.ps

func isOnACPower() -> Bool {
    guard let snapshot = IOPSCopyPowerSourcesInfo()?.takeRetainedValue() else {
        return true // Assume AC if can't determine
    }
    guard let sources = IOPSCopyPowerSourcesList(snapshot)?.takeRetainedValue() as? [Any] else {
        return true
    }
    
    for source in sources {
        guard let info = IOPSGetPowerSourceDescription(snapshot, source as CFTypeRef)?
            .takeUnretainedValue() as? [String: Any] else { continue }
        
        if let powerSource = info[kIOPSPowerSourceStateKey] as? String {
            return powerSource == kIOPSACPowerValue
        }
    }
    return true
}
```

## 8. caffeinate Process (Screen Sleep Alternative)

### Spawning caffeinate as Subprocess

```swift
class CaffeinateProcess {
    private var process: Process?
    
    func start(flags: [String] = ["-d", "-i"]) {
        stop()
        let p = Process()
        p.executableURL = URL(fileURLWithPath: "/usr/bin/caffeinate")
        p.arguments = flags
        try? p.run()
        process = p
    }
    
    func stop() {
        process?.terminate()
        process?.waitUntilExit()
        process = nil
    }
}

// Usage
let caffeinate = CaffeinateProcess()
caffeinate.start()                              // prevent display + idle
caffeinate.start(flags: ["-i"])                 // idle only
caffeinate.start(flags: ["-s"])                 // system sleep (AC only)
caffeinate.start(flags: ["-d", "-i", "-t", "3600"]) // 1 hour timeout
```

#### Gotchas

- `caffeinate -s` (system sleep prevention) only works on AC power on laptops.
- Child process dies if parent app exits — use IOPMAssertion or pmset for robustness.
- Multiple caffeinate processes can run simultaneously — assertions stack.
- `caffeinate` uses IOPMAssertion internally — same mechanism, just spawned as a separate process.
